# Финалдық валидация есебі

## 1. Жұмыстың мақсаты

Дайын бағдарламалық өнімді бастапқы SRS құжатымен салыстыру, функционалдық және функционалдық емес талаптардың орындалуын бағалау және соңғы құжаттама пакетін дайындау.

## 2. Тексеру ауқымы

Тексеру келесі бағыттарды қамтиды:

- SRS талаптарына сәйкестік.
- REST API келісімі.
- Пайдаланушы сценарийлері.
- Деректерді сақтау және өңдеу.
- Қауіпсіздік.
- Өнімділік пен қолжетімділік.
- Автоматты тесттер және CI.
- README және пайдаланушы құжаттамасы.

## 3. Тексеру әдістері

- Инспекция: SRS, OpenAPI, README және архитектуралық құжаттарды тексеру.
- Функционалдық тестілеу: негізгі пайдаланушы сценарийлерін орындау.
- API тестілеу: сұраныстардың мәртебесі мен жауап құрылымын тексеру.
- Қауіпсіздік тестілеуі: авторизацияны, рөлдерді және құпия деректерді қорғауды тексеру.
- Өнімділік тестілеуі: p95 жауап уақытын және жүктеме кезіндегі жүйе жұмысын өлшеу.
- Регрессиялық тестілеу: өзгерістерден кейін бұрынғы функциялардың жұмысын тексеру.

## 4. Валидация нәтижелері

Берілген материалдарда талаптар мен код мысалдары бар, бірақ барлық функциялардың бір жүйеге біріктірілгені және тестілерден өткені расталмаған.

Сондықтан нақты орындалған талаптар саны тест нәтижелері мен бағдарламаның жұмысын тексергеннен кейін толтырылады.

| Көрсеткіш | Нәтиже |
| --- | --- |
| Бастапқы практикалық тапсырмалар | 50 |
| RTM-де көрсетілген талаптар | 15 |
| Орындал��аны дәлелденген талаптар | Әзірге анықталмаған |
| Ішінара орындалған талаптар | Тексеруден кейін анықталады |
| Орындалмаған талаптар | Тексеруден кейін анықталады |
| Тесттердің өту көрсеткіші | Нақты тест нәтижесі қажет |
| Code coverage | Нақты өлшеу қажет |
| Қауіпсіздік аудиті | Нақты есеп қажет |
| Өнімділік тесті | Нақты өлшеу қажет |

Ескерту: 50 практикалық тапсырманың орындалуы мен дайын өнімнің SRS талаптарына сәйкестігі — екі бөлек көрсеткіш. Тапсырма бойынша құжат дайындау функцияның өндірістік ортада жұмыс істейтінін дәлелдемейді.

## 5. Анықталған тәуекелдер

- Кейбір API эндпоинттері тек спецификация түрінде берілген.
- Төлем жүйесімен нақты интеграция расталмаған.
- GPS арқылы курьерді бақылау толық іске асырылғаны расталмаға��.
- Қауіпсіздік, жүктеме және қолжетімділік тесттерінің нәтижелері жоқ.
- Автоматты тесттер бойынша нақты coverage есебі ұсынылмаған.

## 6. Қорытынды

Жобаның құжаттамалық негізі дайындалды: README, OpenAPI спецификациясы, API сипаттамасы, пайдаланушы нұсқаулығы, RTM және валидация есебі.

Өнімнің финалдық қабылдануы барлық міндетті талаптардың тестілеуден өтуіне және нәтижелердің дәлелдермен расталуына байланысты.

## 7. Қабылдау туралы шешім

Мәртебе: финалдық қабылдау үшін қосымша тексеру қажет.

Қабылдауға дейін функционалдық тесттерді орындау, API интеграциясын тексеру, қауіпсіздік аудитін жүргізу және RTM мәртебелерін нақты нәтижелермен толтыру қажет.
